Todo item renderiza o próprio inglês e funciona sem nenhuma configuração. O `FmaI18nProvider` coloca todos em um idioma, com os seus overrides por cima. Ele traduz os textos dos itens: os textos do seu app continuam com o i18next ou a biblioteca que você usar.

## Instalação

```bash
pnpm dlx shadcn@latest add @fma-ds/i18n-pt-br
```

Itens que têm texto já trazem o `@fma-ds/i18n`. O pacote de idioma coloca cada tradução ao lado do seu item, em `<item>-i18n/<item>-pt-BR.ts`, inclusive de itens que você não adicionou: elas só contêm texto e compilam de qualquer forma. Instale o pacote de novo depois de adicionar itens de um registro mais recente.

## Um idioma fixo

```tsx
import { FmaI18nProvider } from "@/lib/fma-ds/i18n/i18n";
import ptBR from "@/lib/fma-ds/i18n-pt-br/i18n-pt-br";

const locales = { "pt-BR": ptBR };

export function App() {
  return (
    <FmaI18nProvider locale="pt-BR" locales={locales}>
      <Routes />
    </FmaI18nProvider>
  );
}
```

Defina `locales` fora do componente, como acima. O provider lê esse objeto uma vez, então uma mudança posterior não tem efeito.

O provider também define o idioma do react-aria, então datas e números nos itens o acompanham.

Coloque-o o mais alto possível na árvore, para que todo item fique dentro dele, inclusive o que monta na raiz, como o `Toaster`. Um item fora dele renderiza em inglês. Só o que ele lê vai acima dele: o `I18nextProvider` com a ponte do i18next, ou o roteador quando o idioma vem da rota. O `Suspense` do seu app vai abaixo dele.

## Precedência

Para cada texto, vence o primeiro destes que o tiver:

1. A prop `i18n` do item.
2. Os `overrides` do provider.
3. O idioma ativo.
4. O idioma de fallback. Ele não se aplica quando o idioma ativo é `en`.
5. O inglês do item.

Um pacote sem um namespace passa para o próximo passo, então um pacote desatualizado continua funcionando.

## Overrides

Não edite uma tradução instalada: atualizar o pacote a sobrescreve. Use `overrides`, que também chegam às funções que montam frases.

```tsx
const overrides = { carousel: { labels: { next: "Avançar" } } };

<FmaI18nProvider locale="pt-BR" locales={locales} overrides={overrides}>
```

Mantenha `overrides` estável também. No servidor, não coloque dados de um usuário em um objeto compartilhado entre requisições.

## Um idioma novo

Um pacote é um objeto com uma entrada por namespace, e pode cobrir só parte deles. O `defineFmaNamespace` confere uma entrada contra o item quando ele está instalado, e a deixa solta quando não está.

```ts
import { defineFmaNamespace, type FmaMessagesPack } from "@/lib/fma-ds/i18n/i18n";

const carousel = defineFmaNamespace("carousel", {
  labels: {
    previous: "Diapositive précédente",
    next: "Diapositive suivante",
    pause: "Mettre en pause",
    start: "Lancer",
    goToSlide: (slide, total) => `Aller à la diapositive ${slide} sur ${total}`,
  },
});

export const fr: FmaMessagesPack = { carousel };
```

`plural`, `number`, `currency` e `date` recebem o locale como primeiro argumento, para as frases que precisarem deles.

## Deixando o provider escolher

Sem `locale`, o idioma fica com o provider. Ele parte de `initialLocale`, depois dos idiomas do navegador, depois de `defaultLocale`. Passe `detect={false}` para ignorar o navegador.

```tsx
const locales = { "pt-BR": () => import("@/lib/fma-ds/i18n-pt-br/i18n-pt-br") };

<FmaI18nProvider locales={locales} defaultLocale="en">
```

Um pacote passado como loader é baixado sob demanda. Enquanto o primeiro pacote carrega, o provider mostra `fallback`, e nada se você não passar um. Em uma troca posterior, os itens mantêm o idioma antigo até o pacote chegar, então os idiomas nunca se misturam na tela.

O provider é uma fronteira de Suspense, então também captura o que suspende dentro dele, como uma rota lazy. Uma fronteira acima dele nunca aparece. Coloque o seu `Suspense` dentro do provider, ou passe o mesmo conteúdo como `fallback`:

```tsx
<FmaI18nProvider locales={locales} fallback={<Spinner />}>
```

`useFmaLocale` dá a um seletor de idioma o que ele precisa, e devolve `null` sem provider:

```tsx
const { locale, locales, isPending, setLocale } = useFmaLocale();
```

## Idioma pela rota

Passe o idioma da rota como `locale` e navegue em `onLocaleChange`. Com `locale` definido, `setLocale` só chama `onLocaleChange`.

```tsx
<FmaI18nProvider
  locale={params.lang}
  locales={locales}
  onLocaleChange={(lang) => navigate({ params: { lang } })}
>
```

Qualquer outra biblioteca que controle o idioma se conecta da mesma forma.

## Renderização no servidor

Carregue o pacote no loader da rota, para o provider não suspender, e repasse o resultado. O idioma escolhido pelo servidor vence o do navegador durante a hidratação. Sem `initialLocale` ou `locale`, um app com detecção ligada renderiza um idioma diferente em cada lado e a hidratação falha.

```ts
const requested = parseAcceptLanguage(request.headers.get("accept-language"));
const locale = await loadFmaMessages(locales, requested);
```

Cada provider tem o próprio store, então requisições simultâneas nunca compartilham um idioma.

## Com i18next

```bash
pnpm dlx shadcn@latest add @fma-ds/i18n-i18next
```

Os textos do seu app continuam no i18next, que também detecta o idioma. O `FmaI18nextProvider` mantém os itens no mesmo idioma e usa o `fallbackLng` como fallback.

```tsx
import { I18nextProvider } from "react-i18next";
import { changeLanguage, FmaI18nextProvider } from "@/lib/fma-ds/i18n-i18next/i18n-i18next";

<I18nextProvider i18n={i18n}>
  <FmaI18nextProvider locales={locales}>
    <App />
  </FmaI18nextProvider>
</I18nextProvider>;

await changeLanguage(i18n, "pt-BR", locales);
```

- **Pacotes estáticos**, importados como o `ptBR` acima, trocam na hora, seja qual for a forma de mudar o idioma. Prefira esses.
- **Pacotes atrás de um loader** precisam do `changeLanguage` acima: ele carrega o pacote primeiro e só então troca o i18next, então o app e os itens mudam juntos. Com `i18n.changeLanguage`, os itens mantêm o idioma antigo até o pacote chegar.
- `useFmaLocale().setLocale` também passa pelo `changeLanguage`.
- No servidor, crie uma instância por requisição com `i18next.createInstance()`.

Variáveis, plurais e `<Trans>` nos seus próprios textos seguem a [documentação do i18next](https://www.i18next.com).

## Máscaras e formatos

As máscaras de decimal e de data do `MaskedInput` seguem o provider: separadores e ordem da data vêm do idioma. Quando ele muda, o texto é refeito a partir do valor bruto, que permanece o mesmo. Um parâmetro explícito na máscara vence, e sem provider as máscaras continuam brasileiras. Máscaras de documentos mantêm seus formatos fixos.

## Outras bibliotecas

As traduções dos itens não chegam às bibliotecas que o seu app usa diretamente. Configure-as onde o idioma muda, em `onLocaleChange` ou no `languageChanged` do i18next:

```ts
import { z } from "zod";
import { setDefaultLocale } from "@/lib/fma-ds/date-fns-compat";

i18n.on("languageChanged", (lng) => {
  z.config(lng === "pt-BR" ? z.locales.ptBR() : z.locales.en());
  setDefaultLocale(lng);
  document.documentElement.lang = lng;
});
```
