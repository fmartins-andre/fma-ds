Every item renders its own English and works without any setup. `FmaI18nProvider` puts all of them in one language, with your overrides on top. It translates the items' texts: your app's texts stay with i18next or whichever library you use.

## Install

```bash
pnpm dlx shadcn@latest add @fma-ds/i18n-pt-br
```

Items that have text already bring `@fma-ds/i18n`. The language pack places each translation next to its item, in `<item>-i18n/<item>-pt-BR.ts`, including items you haven't added: they only hold text and compile either way. Install the pack again after adding items from a newer registry.

## A fixed language

```tsx
import { FmaI18nProvider } from "@/lib/fma-ds/i18n/i18n";
import ptBR from "@/lib/fma-ds/i18n-pt-br/i18n-pt-br";

const locales = { "pt-BR": ptBR };

export function App() {
  return (
    <FmaI18nProvider locale="pt-BR" locales={locales}>
      <Routes />
    </FmaI18nProvider>
  );
}
```

Define `locales` outside the component, as above. The provider reads it once, so a later change to it has no effect.

The provider also sets the language of react-aria, so dates and numbers in the items follow it.

## Precedence

For each text, the first of these that has it wins:

1. The item's `i18n` prop.
2. The provider's `overrides`.
3. The active language.
4. The fallback language. It doesn't apply when the active language is `en`.
5. The item's English.

A pack that misses a namespace falls through to the next step, so an outdated pack still works.

## Overrides

Don't edit an installed translation: updating the pack overwrites it. Use `overrides`, which also reach the functions that build sentences.

```tsx
const overrides = { carousel: { labels: { next: "Avançar" } } };

<FmaI18nProvider locale="pt-BR" locales={locales} overrides={overrides}>
```

Keep `overrides` stable too. On the server, don't put one user's data in an object shared between requests.

## A new language

A pack is an object with one entry per namespace, and it can cover only part of them. `defineFmaNamespace` checks an entry against the item when the item is installed, and leaves it loose when it isn't.

```ts
import { defineFmaNamespace, type FmaMessagesPack } from "@/lib/fma-ds/i18n/i18n";

const carousel = defineFmaNamespace("carousel", {
  labels: {
    previous: "Diapositive précédente",
    next: "Diapositive suivante",
    pause: "Mettre en pause",
    start: "Lancer",
    goToSlide: (slide, total) => `Aller à la diapositive ${slide} sur ${total}`,
  },
});

export const fr: FmaMessagesPack = { carousel };
```

`plural`, `number`, `currency` and `date` take the locale as their first argument, for the sentences that need them.

## Letting the provider choose

Without `locale`, the provider owns the language. It starts from `initialLocale`, then the browser's languages, then `defaultLocale`. Pass `detect={false}` to skip the browser.

```tsx
const locales = { "pt-BR": () => import("@/lib/fma-ds/i18n-pt-br/i18n-pt-br") };

<FmaI18nProvider locales={locales} defaultLocale="en">
```

A pack given as a loader is fetched on demand. While the first pack loads the provider shows `fallback`, and nothing if you don't pass one. On a later change the items keep the old language until the pack arrives, so languages never mix on screen.

The provider is a Suspense boundary, so it also catches whatever suspends inside it, like a lazy route. A boundary above it never shows. Put your own `Suspense` inside the provider, or pass the same content as `fallback`:

```tsx
<FmaI18nProvider locales={locales} fallback={<Spinner />}>
``` `useFmaLocale` gives a language selector what it needs, and returns `null` without a provider:

```tsx
const { locale, locales, isPending, setLocale } = useFmaLocale();
```

## Language from the route

Pass the route's language as `locale`, and navigate in `onLocaleChange`. With `locale` set, `setLocale` only calls `onLocaleChange`.

```tsx
<FmaI18nProvider
  locale={params.lang}
  locales={locales}
  onLocaleChange={(lang) => navigate({ params: { lang } })}
>
```

Any other library that owns the language plugs in the same way.

## Server rendering

Load the pack in the route's loader, so the provider doesn't suspend, and pass the result on. The language the server chose wins over the browser's during hydration. Without `initialLocale` or `locale`, an app with detection on renders a different language on each side and hydration fails.

```ts
const requested = parseAcceptLanguage(request.headers.get("accept-language"));
const locale = await loadFmaMessages(locales, requested);
```

Each provider has its own store, so simultaneous requests never share a language.

## With i18next

```bash
pnpm dlx shadcn@latest add @fma-ds/i18n-i18next
```

Your app's texts stay in i18next, which also detects the language. `FmaI18nextProvider` keeps the items in the same language and takes the fallback from `fallbackLng`.

```tsx
import { I18nextProvider } from "react-i18next";
import { changeLanguage, FmaI18nextProvider } from "@/lib/fma-ds/i18n-i18next/i18n-i18next";

<I18nextProvider i18n={i18n}>
  <FmaI18nextProvider locales={locales}>
    <App />
  </FmaI18nextProvider>
</I18nextProvider>;

await changeLanguage(i18n, "pt-BR", locales);
```

- **Static packs**, imported like `ptBR` above, switch at once however you change the language. Prefer them.
- **Packs behind a loader** need the `changeLanguage` above: it loads the pack first, then switches i18next, so the app and the items change together. With `i18n.changeLanguage`, the items keep the old language until the pack arrives.
- `useFmaLocale().setLocale` goes through `changeLanguage` too.
- On the server, create an instance per request with `i18next.createInstance()`.

Variables, plurals and `<Trans>` in your own texts follow [i18next's documentation](https://www.i18next.com).

## Masks and formats

Decimal and date masks in `MaskedInput` follow the provider: separators and date order come from the language. When it changes, the text is redrawn from the raw value, which stays the same. An explicit parameter on the mask wins, and without a provider the masks stay Brazilian. Masks for documents keep their fixed formats.

## Other libraries

The items' translations don't reach libraries your app uses directly. Set them where the language changes, in `onLocaleChange` or i18next's `languageChanged`:

```ts
import { z } from "zod";
import { setDefaultLocale } from "@/lib/fma-ds/date-fns-compat";

i18n.on("languageChanged", (lng) => {
  z.config(lng === "pt-BR" ? z.locales.ptBR() : z.locales.en());
  setDefaultLocale(lng);
  document.documentElement.lang = lng;
});
```
